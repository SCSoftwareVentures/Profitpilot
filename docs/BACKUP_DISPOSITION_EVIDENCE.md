# Independent backup disposition evidence verification

Candidate-only offline verifier: scripts/verify-backup-disposition.js. It checks the exact consumed work-order identity, tenant, allocation receipt, approved inventory and plan hashes, UTC review date, sorted unique copy identifiers, per-copy retention deadlines (inclusive), permitted method, completion time, and actual evidence document bytes. Require four separate externally pinned Ed25519 signers (counsel, custodian, independent assessor, owner), a short-lived signed verification statement, exact per-copy coverage and bounded evidence inputs. Inventory and plan hashes must be obtained independently from the authoritative reviewed record; do not trust caller-created expected values or keys in a submitted bundle. No real keys or evidence are embedded; unit test keys and dates are synthetic.

The verifier only returns signed-evidence-verified and explicitly denies disposal authority and proof of physical erasure. It does not execute destruction, read live holds, verify actual media/replicas/provider deletion, establish legal policy completeness or prove signer independence. An actual approved operational procedure and independent acceptance are still required. Do not use this verifier as a deletion gate. No new runtime access or production activation.

CI now persists the authorised synthetic payroll correction/retention/backup-plan fixture before encrypted backup, validates the populated records and audit chain after restore, tests runtime and mutation denial, and checks that independently signed authoritative inventory mismatches for a newer hold or plan require isolation of an older snapshot. The post-snapshot perturbations are transactionally rolled back; they deliberately simulate trusted administrator changes to isolate the fingerprint test, not a valid new backup approval. No real production data or media.
