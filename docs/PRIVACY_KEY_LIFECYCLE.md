# Case key lifecycle and compromise controls (candidate only)

Migration 062 adds immutable case-scoped generations of three distinct independently reviewed fingerprints: recipient encryption, sender signature and recipient acknowledgement signature. Enrollment and replacement require exact evidence, a separate fresh-MFA security work order, different active reviewer and original requester consuming the approval. The predecessor must be the current generation. A retired fingerprint cannot be reintroduced into the same case or substituted across roles. Any active owner/admin with a signed fresh-MFA action can immediately and permanently deny a suspect key fingerprint across the tenant; even an unregistered fingerprint can be blocked. A subsequent generation must replace all compromised keys it would otherwise carry. Common tenant lock serializes key mutations and release/dispatch/receipt eligibility. Historical authorization, dispatch and receipt records remain immutable. New release, reserve, burn and new receipt review fail when enrolled key versions do not match or known compromise is recorded. Previously opened unregistered synthetic cases remain compatible but are not authorized for live delivery. Existing recorded receipts remain historical assertions, not revalidated proof.

No public key bytes or private keys, custody, actual compromise detection telemetry, external certificate revocation, automatic rotation, transport or new runtime permissions. Digests are independently reviewed assertions; actual identity/ownership and key provenance must be verified externally. Protective revocation through this private operator procedure requires an available tenant and an authenticated active administrator; tenant-wide containment remains a separate emergency control. A case must be mutually enrolled before any future production integration; the current synthetic API does not mandate enrollment for legacy cases. Existing status labels describe the dispatch ledger, not current key eligibility. Production remains closed. Signed recovery inventory incorporates both new ledgers and requires reissue. Tests use only synthetic digests and check independent rotation, scope substitution, retired/compromised key rejection, replay, immutable history and encrypted restore. No external release or independent certification.
