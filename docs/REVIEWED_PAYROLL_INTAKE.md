# Reviewed pre-minimized payroll intake (candidate)

Migration 063 introduces a restricted offline source mapping contract and private repository-level intake workflow. No real payroll upload, provider integration, runtime grants, employee data or tax/payroll processing. The input is already minimized by a trusted upstream procedure: exactly source_row_key,amount,currency in ASCII, exact LF line endings, trailing LF, AUD only, canonical nonnegative 2-decimal values, 1–200 rows, opaque ppr_ plus 64 lowercase hexadecimal token (stable keyed pseudonym supplied by the source custodian, never a raw employee ID), explicit source namespace, period, exact byte digest, row count and control total, independent authority, source control and policy evidence digests. Reject unknown columns, malformed amounts, negative/reversals, duplicates, mixed currency, mismatches and overlapping tenant payroll periods. The overlap rule is intentionally conservative; legitimate multiple overlapping entities or corrected source versions require a separately designed reconciliation path. Pseudonyms are not proof of anonymization; original mapping, provenance and keyed pseudonym generation must be independently verified, retained in approved custody and never enter the public repository. Only synthetic input supported.

The JS inspector produces pending independent review, never approval. PostgreSQL independently validates the exact narrow payload, reconstructs the byte hash, checks registration/holds/replay, reconciles exact decimals, and binds all source/authority/control fields into the dual-authorized work order. On consume, one transaction populates one accepted batch, one authoritative pool, raw minimized rows and linked immutable source rows and intake receipt. No allocation or confirmed financial result is produced. New guards preserve reviewed managed source records before allocation, not just after confirmation; existing legacy paths are not promoted to reviewed intake. Private tables/functions have no application grants; an authenticated operator API, clean source preparation and allocator integration remain to be built. No live raw payroll file intake or real source system is enabled; source custody, approved policies (including signed negative adjustments and cost components), production scanner and legal/financial specialist acceptance still required. Recovery inventory includes new receipt; reissue inventories after migration. Synthetic tests cover parser, database control totals, exact source hash, independent approval, replay, immutability, recovery and restricted privileges.
