# Candidate dispatch operator API

Migration 061 exposes only the exact signed status and reserve/burn/revoke operation under recent MFA and active owner/admin membership. Reserve and burn require the original release requester and a still-valid independent approval; revocation is immediate and irreversible for an authenticated owner/admin. The API requires an existing API release reservation and immutable authorization, does not accept URLs, documents, tokens, private keys or raw challenge material. The synthetic UI records opaque digests and a UTC epoch expiry. Both mayTransmit and deliveryVerified remain false. For releases with a dispatch reservation, receipt reconciliation now requires the exact challenge and recipient signing key from a spent attempt; historical receipts can be reviewed after revocation and legacy offline evidence remains supported. The synthetic end-to-end integration now commits reserve and burn prior to the isolated loopback transfer. A separate authenticated test exercises concurrent requests and revocation; either transaction ordering is allowed but at most one burn commits and revocation cannot be undone. This is not an atomic external network fence: a committed burn is not a delivery permit, external transmission is disabled, and the isolated test harness is not production infrastructure. Independent operational/legal acceptance, current key custody, recovery coordination and durable transport remain outstanding. No real data or destinations.
