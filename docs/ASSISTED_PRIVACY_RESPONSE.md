# Assisted privacy response candidate

Migration 056 provides an operator-only, private database authorization workflow for a reviewed privacy case response. It binds the exact case decision, order UUID, verified recipient type (self, assisted subject, authorized representative or former user), independently verified X25519 recipient key fingerprint, trusted Ed25519 sender fingerprint, authority/redaction evidence digests, response digest and exact envelope digest. A recorded acknowledgement and independent case decision are required; identity-not-verified cases are denied. A distinct active owner/admin must approve the request; the original requester consumes one fresh-MFA, expiring approval. Revoked approval, substituted scope, duplicate/replayed envelope and cross-tenant access are denied. Consumed authorization and minimal audit are append-only and included in signed recovery state. Case outcomes describe recorded decisions, not proof of delivery.

The offline envelope helper in scripts/privacy-response-envelope.js encrypts up to 1 MiB with ephemeral X25519, HKDF-SHA-256 and AES-256-GCM, authenticates the exact tenant/case/order and recipient/sender pins, signs the package with Ed25519, and verifies the independently obtained approved envelope hash and sender pin before decrypting for the nominated recipient. It never stores or transmits a response. The encrypted envelope excludes plaintext and response hash, but context must be exchanged via an approved private channel. Do not publish context, hashes, keys, ciphertext or actual responses in the public repository. The caller must obtain the expected scope and key pins independently from the trusted operator record. No external delivery, private-key custody, proof of actual identity, independent legal redaction, delivery receipt or production endpoint is implemented. The offline seal/open helpers are not authorisation or a substitute for current legal, identity and hold verification at release time. Actual fulfilment needs a controlled transport with recipient identity confirmation, secure key lifecycle and delivery/receipt reconciliation. This candidate has no new runtime permissions or live activation.

CI executes signed synthetic scope, approval, revocation, cross-tenant, replay and immutable-ledger tests and includes a populated authorised release in the encrypted restore exercise. The envelope tests use synthetic keys and bytes, including forged ciphertext rehashed by an attacker, sender/recipient substitution, malformed encoding, context changes and size limits. No personal data, production keys or live disclosure.
