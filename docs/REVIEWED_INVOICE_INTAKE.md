# Reviewed customer invoice materialization (synthetic candidate)
Migration 068 connects encrypted scanned/promoted CSV manifests to the authoritative invoice, invoice-line and confirmed match ledger. It accepts only explicitly mapped customer invoice rows with all eleven approved columns, positive canonical AUD amounts and exact independent count, amount and evidence controls. Existing managed customer, contract, site label/ID and contract-site assignment must match; the approved baseline covers each service period and currency/tax basis. No arbitrary inferred matches, supplier invoices, negative credits, duplicate payload rows or case-insensitive repeated invoice reference across batches. A multi-line invoice must share customer, date and tax basis. Scanned manifest hash is reconstructed from persisted ordered payloads; direct parsed row intake cannot bypass scanning. Exact scope binds row IDs, mapping, baseline, controls and file hash. MFA and a separate approved security work order precede atomic materialization; reviewer is the independent approver. The source batch, invoice headers, lines, matches and link ledger are protected from modification and append after consumption. No blanket grants. The candidate UI registers and uploads the exact selected file, requests scan promotion (separate worker needed), previews the mapping and records review actions; it does not launch a scanner automatically. Actual worker integration is tested using a synthetic clean callback; real ClamAV remains separately tested by operational CI. Evidence pointers are assertions, not real proof of invoice authenticity or independent financial acceptance. Credits, supplier vendor identities, invalid or partially mapped batches, invoice corrections, multiple same-number customer invoices, richer line metadata, and production custody remain outstanding. No live data or production release. Recovery fingerprint includes reviewed orders, receipts, and line links; reissue signed inventories after migration.
