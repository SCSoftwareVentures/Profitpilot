# Dual-control operator access provisioning (development implementation)

The application has no self-enrolment or unauthorised membership-management endpoint. Migration 053 provides two separately delegated SQL roles. Use named non-superuser login accounts with independent operator authentication, external authority evidence and least privilege. Both groups are empty by default; never grant both, incident operator groups, or direct table privileges to the same login. The proposal procedure stores only a SHA-256 digest of the exact JSON body, operator role name, authority-evidence digest and short-lived intent; it does not retain provider subject, email or tenant name in pending receipts.

1. Verify business ownership, identity provenance and explicit tenant authority outside the database. Retain confidential documentation separately. The proposer constructs a bounded JSON string and passes it with a digest of the authority evidence to private.prepare_access_change(text,text). Supported actions: create_tenant (initial owner, exact tenant/user UUID, name, verified issuer/subject/email), grant (exact identity and role), role (existing member and role), revoke (existing member). The exact original string is required for approval, including ordering and whitespace.
2. An independently authenticated access approver reviews the exact change and separate evidence, then calls private.execute_access_change(uuid,text,text) within 15 minutes. The function rejects changed, expired or consumed requests, closed/contained accounts, mismatched existing identities and removal of the final active owner. It creates no external account and never changes a provider binding. Existing role overrides are cleared during approved membership changes. The runtime cannot execute these procedures or read the evidence table.
3. Inspect the returned minimal result, independently test intended access and capture a signed restore checkpoint. Recovery of revoked membership needs a new grant with exact authority evidence. This is not an external provider session revocation. Session and membership enforcement blocks future local tenant operations; pre-existing snapshot reads may finish.

Production operator MFA, trusted business authority validation, provider account creation and evidence custody are external release gates. SQL approval digests are operator attestations, not proof of the external documents' authenticity. No tenant/customer account or operator credential is provisioned against production by this code.
