# Integrated candidate workspace
The non-production-only, opt-in route /candidate/workspace/ provides a responsive, authenticated same-origin interface for workspace setup, site assignment, exact commercial baseline review, jobs/readiness, minimized payroll registration, independently reviewed intake, allocation proposal and confirmation, and management calculation/read/export. It uses actual server routes and preserves explicit confirmation, no-store, MFA/role enforcement, exact decimal and source controls. It does not simulate success or invent financial data. The separate /candidate/security/ workbench remains for privacy and incident operations. The legacy app/index.html is an offline visual demonstration, not the connected product.
 
To evaluate: use a locally run synthetic development candidate with a reviewed test database and independently configured synthetic identity issuer; set SYNTHETIC_SECURITY_UI_ENABLED=true explicitly (default off), keep the application on loopback, and open http://127.0.0.1:8080/candidate/workspace/ on the buyer's computer. Connect the supplied tenant UUID and a short-lived synthetic MFA token. No public hosting or production identity is required or enabled. Browser crypto requires a secure context (loopback qualifies in supported browsers). Use two independently provisioned test identities for approval and consumption; record the order IDs and exact synthetic data outside the UI using an approved test procedure, then clear and reconnect when switching roles. Sessions clear on credential change and page exit, no local storage or cookies; writes are never automatically retried. A lost response requires reading the exact ID before deciding whether to retry. Report export is shown as the audited JSON response; file download and human-formatted reporting remain outstanding.

Test evidence: node tests check exact parser/hash, tenant path, assignment selectors, mapping/form wiring, and forbidden persistent storage/external links; authenticated HTTP integration tests check opt-in static assets, CSP/cache headers and real API workflow.
