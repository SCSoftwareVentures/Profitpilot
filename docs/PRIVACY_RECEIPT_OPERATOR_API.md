# Authenticated receipt-evidence reconciliation (candidate only)

Migration 059 exposes exact preview, status and request/approve/reject/consume operations for active owner/admin identities with recent MFA. The release must have an authenticated API reservation and an existing immutable authorization; the receipt review has a separate UUID and independently signed work order. PostgreSQL independently checks tenant, case, release, review, digests, fresh identity, distinct reviewer and single-use consumption. Request reservation is append-only and included in signed recovery inventories. Multiple pending reviews cannot record two receipts for one release. The status distinguishes evidence recorded from verified delivery; deliveryVerified stays false. Only opaque evidence digests enter this API; the actual receipt and verified key must be independently checked with the offline helper and retained in approved private custody. UI is synthetic only. No endpoint accepts documents, key bytes, raw signed records, addresses, or transport destinations; no live delivery or legal approval. The operator's confirmation is an assertion of independently reviewed evidence, not cryptographic verification inside the database. No deletion, external access or production activation is enabled. CI covers malformed requests, unauthorized and cross-tenant access, self-approval, exact evidence binding, replay and minimized status. Reissue signed recovery inventories after migration. Real delivery/key custody and independent operational and legal acceptance remain external requirements.
