# Durable dispatch fence (candidate only)

Migration 060 adds append-only reservation, spent-attempt and protective revocation ledgers. Each release can reserve one challenge and independently checked recipient signing key with an exact bounded expiry. A fresh-MFA signed action from the original release requester rechecks the original independent approval, expiry, active reviewer and session revocation. All actions serialize on the release authorization row. Before transmission a future trusted dispatcher would need to commit a spent-attempt record; replay or automatic re-arming is prohibited. Any active owner/admin with recent MFA may record an immediate irreversible protective revocation, including before reservation or after an ambiguous attempt. A revocation cannot recall already transferred bytes or erase historical receipt evidence. Receipt reconciliation remains historical evidence, not proof of dispatch; no new receipt requirement is imposed on existing synthetic or offline cases.

This implementation returns mayTransmit=false and deliveryVerified=false in every state. No external transport, dispatch token, application or worker grant, live sender, key custody, or production activation. The existing synthetic courier is still separate and in-memory. The ledger accepts reviewed evidence digests, not independently authenticated challenge bytes or proof of a real physical event. The committed reservation/attempt is not permission to send; external release remains disabled. A production dispatcher would need separately reviewed committed-state coordination, revocation fencing through the irreversible network boundary, trusted current identity and challenge verification, transactional failure handling and independent operational/legal acceptance. In-flight external transfer cannot be made atomically transactional with a database. The safe response to a crash or lost response is to treat the prior attempt as spent; never retry by restoring an old snapshot. Signed recovery fingerprints include all three ledgers; old snapshots with differing authoritative state must stay isolated and require manual reconciliation. Reissue signed inventories after migration.

CI exercises the private signed controls, unreserved attempts, cross-tenant denial, immediate pre-reservation revocation, original approver revocation, challenge substitution, replay, immutability, runtime privilege denial, populated encrypted restoration and mismatch isolation after a newer protective revocation. Synthetic digests only. No real delivery or certification.
